Dashboard widgets — three additions

Three new widgets for / (the V4 Dashboard at routes/+page.svelte): Daily MVP strip, Personal Trail strip, and Pool Distribution histogram. All three appear as a full-width section below the existing two-column grid — spanning the full container, stacked vertically. Nothing in the existing grid moves; both columns keep all their current widgets in the same order. All three respect blind-pool: hidden pre-deadline.

① Daily MVP strip New

A row of "top scorer per day" cards, most-recent-first. Fixed at the last 5 days — no scroll bar. Chips flex to share row width on desktop; wrap to multiple rows on narrow viewports. Today's chip is gold-tinted for emphasis.

What's on each chip

  • Date ("Today · Jun 22" for the most recent, "Jun 21" / etc for older)
  • Person — Entry (uses the same rowDisplayName rule from leaderboardV4.ts — only shows entry name when the person has multiple entries)
  • Points scored that day in mint (always positive — the MVP scored more than anyone)
  • Rank delta with gold ▲ for up, faded red ▼ for down (rank can fall on a high-scoring day if others scored more)

Rules & edge cases

  • Tie-break: equal day-points → lower current rank wins. Ties show one MVP only (not two).
  • Zero-points day: chip is omitted entirely (no "Nobody scored" placeholder).
  • Pre-deadline: whole strip is hidden (blind-pool gate).
  • Click a chip: opens EntryDrawer for the MVP, scrolled to that day's row.

Backend

GET /api/leaderboard/daily-mvps → returns up to 5 entries { captured_date, subject_entry_id, user_name, entry_name, day_points, rank_delta }. Derived from LeaderboardSnapshot day-over-day diffs. Cached 60s. Fixed window — no query param.

② Personal Trail strip New

A horizontal sparkline comparing your cumulative points to the pool average over the tournament. Signed-in users only.

Three layout regions (left → right)

  • Identity column: entry name + current rank + legend ("You" gold / "Pool avg" grey)
  • Sparkline: two cumulative-points lines over the tournament. End dots show today's values.
  • Headline stat: "+47 pts" in mint (or red if behind) labelled "vs pool avg"

Multi-entry users

Show ONE strip per entry, stacked vertically with a 4px gap. Users with 3+ entries see the first 2 by default with a "+1 more" link to expand. Avoids a wall of charts for the multi-entry edge case (some users have 4+).

Edge cases

  • Signed-out / zero entries: hidden.
  • Day 1: two single-point dots side by side. Adds a faint "It's early." caption.
  • Pre-deadline: hidden (can't compute pool average yet).

Backend

GET /api/leaderboard/personal-trail → returns the requesting user's entries' trails: { entry_id, points: [{captured_date, your_points, pool_avg_points}], current_gap }. Pool average is the mean across eligible entries per day (matches the "scoring pool" definition from CLAUDE.md).

③ Pool Distribution histogram New

A small histogram showing how the leaderboard clusters around your current points total. Helps you gauge how reachable the next rank is.

What's on the chart

  • X-axis: points-from-your-total, range ±5 by default. Bins are 1pt wide.
  • Y-axis: count of entries at that point total.
  • Your bar: bright gold, centred.
  • Neighbours (±2pt): gold-mid tint.
  • Outside ±2: grey.
  • Next-rank marker: dashed mint line at the points value where the next-higher rank starts.

Caption above the chart

"X entries within N points of you. The next rank is M points away." Dynamic — copy adapts to "you are tied with K entries" / "you're alone at this score" / etc.

Edge cases

  • Signed-out / zero entries: hidden.
  • Pre-deadline: hidden.
  • User at #1: caption changes to "Nobody within X points of you above" + "Closest pursuer N points behind."
  • Sparse pool (≤ 2 entries within ±5): widen the window to ±10 automatically.

Backend

GET /api/leaderboard/pool-distribution → returns the histogram around the requesting user. { user_points, window_size, bins: [{points_delta, count}], next_rank_points_away, near_count }. Pure aggregate from the existing leaderboard rows; ~50ms even cold.

Decisions

Locked

  • Placement: all three widgets in a NEW full-width region below the existing two-column grid, spanning both columns. Both the LEFT (Main) and RIGHT (Side) columns are entirely untouched — every existing widget keeps its current position.
  • Width: full container width (~1180px desktop). MVP strip shows ~6 chips at once on desktop, scrolls for more. Personal Trail uses the original three-column horizontal layout (identity / sparkline / stat). Pool Distribution gets 13 wide bins.
  • Stacking order within the new region: Daily MVP → Personal Trail → Pool Distribution. Editorial first (pool-wide), then personal (your own performance), then positional (how reachable nearby ranks are). Reads as a narrative from broad to specific.
  • Ship together: yes — they share backend infrastructure (same snapshots table, same blind-pool gate, same caching).

Remaining

  1. Bundle with leaderboard race redesign, or separate PR? Recommendation: separate PR after race redesign merges. Different surface, different reviewability, cleaner rollback story.
  2. Multi-entry handling in Personal Trail: "show first 2, link to expand" vs "show all stacked." Recommended: first 2 + expand — keeps the column manageable for users with 4+ entries.
